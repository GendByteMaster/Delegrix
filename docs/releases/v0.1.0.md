# Delegrix v0.1.0 — Intelligent AI Subagent Delegation

**Delegate intelligently. Execute safely. Verify everything.**

Delegrix is a portable, instruction-only **Agent Skill** for structured AI subagent delegation. It helps a primary coding agent decide when delegation is beneficial, define measurable task goals, divide work into independent scopes, control file ownership, collect evidence, and integrate verified results.

This is the first public release, with a portable CLI for **Codex, Claude Code, and Cursor**, offline preflight checks, and optional interoperability with **ForgeGuard** and **ForgeScope**.

## What's included

- **Adaptive delegation:** use only the workers justified by genuinely independent tasks, runtime capacity, and explicit user approval.
- **Task-local Goal:** define or reuse an observable outcome, success criteria, evidence, scope, and stop/escalation conditions in the current task.
- **ForgeGuard integration:** automatically attempt to load the installed engineering guardrails and apply applicable authorization, Goal Intelligence, Risk Gate, delegation, and verification policies.
- **ForgeScope integration:** automatically attempt to load the installed review Skill and apply an appropriately scoped review with evidence-backed findings.
- **Bounded worker contracts:** clear objective, owned and excluded paths, dependencies, permissions, acceptance criteria, and required handoff.
- **Safe parallel work:** non-overlapping write ownership, dependency-aware waves, optional worktree isolation, and explicit handling of failed workers.
- **Evidence-based integration:** review actual diffs, tests, findings, and handoffs before accepting delegated work.
- **Offline preflight validation:** check proposed JSON delegation plans for structural mistakes and policy conflicts. A passing preflight does **not** authorize worker execution.
- **Portable CLI:** `install`, `update`, `status`, and `uninstall`, supporting user-level and project-level installation.
- **Automated checks:** Python scenario/packaging tests and Node.js CLI lifecycle tests, with Linux and Windows CI coverage.

### How the three Skills work together

```text
Delegrix invoked
    |
    v
ForgeGuard (if installed) — authorization, Goal Intelligence, risk policy
    |
    v
Task-local Goal — outcome, success criteria, verification evidence
    |
    v
ForgeScope (if installed) — scoped code review and findings
    |
    v
Delegrix — bounded assignments, ownership, handoffs, integration
    |
    v
Primary agent — final verification and completion decision
```

**Important:** Delegrix attempts to activate the companion Skills using the host's supported mechanism. Otherwise, it loads and applies their installed instructions and reports `instructions-loaded`. It does not start standalone ForgeGuard or ForgeScope processes, install them implicitly, or bypass their policies. Both companion installations are optional.

## Requirements

- **Node.js 18 or later**, with npm/npx, and Git available for GitHub-based package installation.
- A coding agent that supports Agent Skills (Codex, Claude Code, or Cursor).
- Actual subagent execution additionally requires a capable host/runtime and **explicit authorization from the user in the current conversation**.

No npm-registry publication is required to install directly from GitHub.

## Install

Run these commands in PowerShell, Windows Terminal, macOS Terminal, or a Linux shell.

### Codex — install for your user account (recommended)

```powershell
npx --yes "github:GendByteMaster/Delegrix#v0.1.0" install --client codex --global
```

User-level location: `~/.agents/skills/delegrix/`.

### Codex — install only in the current repository

Run from your project's root directory:

```powershell
npx --yes "github:GendByteMaster/Delegrix#v0.1.0" install --client codex
```

Project-level location: `.agents/skills/delegrix/`.

### Claude Code

```powershell
npx --yes "github:GendByteMaster/Delegrix#v0.1.0" install --client claude --global
```

User-level location: `~/.claude/skills/delegrix/`. Without `--global`, installs into `.claude/skills/delegrix/` in the current project.

### Cursor

```powershell
npx --yes "github:GendByteMaster/Delegrix#v0.1.0" install --client cursor --global
```

User-level location: `~/.cursor/skills/delegrix/`. Without `--global`, installs into `.agents/skills/delegrix/` in the current project.

### Install for all three clients

```powershell
npx --yes "github:GendByteMaster/Delegrix#v0.1.0" install --client all --global
```

Codex and Cursor share the project-level `.agents/skills/delegrix/` path; the installer deduplicates it.

### Verify installation

```powershell
npx --yes "github:GendByteMaster/Delegrix#v0.1.0" status --client codex --global
```

Look for `installed v0.1.0`. Restart your coding-agent session if the Skill is not discovered immediately.

## Update an existing installation

**Update to the latest source on the default `main` branch:**

```powershell
npx --yes github:GendByteMaster/Delegrix update --client codex --global
```

**Preview an update without writing files:**

```powershell
npx --yes github:GendByteMaster/Delegrix update --client codex --global --dry-run
```

**Reapply this exact released version (v0.1.0):**

```powershell
npx --yes "github:GendByteMaster/Delegrix#v0.1.0" update --client codex --global
```

Use `--client claude`, `--client cursor`, or `--client all` for other targets; omit `--global` for a project-local installation. Restart the coding agent after updating.

The `update` command compares files shipped by the invoked Delegrix package against an **existing managed** installation. It copies changed or missing shipped files, leaves unchanged files alone, and preserves unrelated user files. It refuses missing or unmanaged installations and unsafe symbolic-link paths. It may overwrite local edits to Delegrix-managed files; put custom repository rules in project instructions instead.

**Update is not a background updater.** The version comes from the package source supplied to `npx`. The pinned `#v0.1.0` command never advances beyond this tag. For later releases, replace the tag (for example, `#v0.2.0` once that version actually exists), or use the unpinned GitHub command to use current `main`. Running a permanently installed `delegrix update` does not independently fetch a new CLI version.

If Delegrix is not installed yet, use `install` first. To refresh an installed managed Skill using the installer, `install --force` is also supported.

## Optional companion Skills

If you also want ForgeGuard and ForgeScope available in Codex, install them separately:

```powershell
npx --yes github:GendByteMaster/ForgeGuard install --client codex --global
npx --yes github:GendByteMaster/ForgeScope install --client codex --global
```

Delegrix does not install, update, or modify their managed configurations.

## Example usage

After installation, start a new coding-agent session in an actual project and ask:

> Use $delegrix to implement the current task. Apply ForgeGuard and ForgeScope if installed, define or reuse a measurable Goal in the current task, and verify all results. You may use up to 2 subagents for this task only. Keep implementation scopes separate, use a read-only independent review when useful, and report actual workers launched and verification evidence.

Authorizing subagents permits their use **when useful**; it does not force a specific worker count. If the host cannot launch them, Delegrix must report that limitation rather than invent worker activity.

## Validation and known limitations

- CI covers Python 3.11/3.13 and Node.js 18/20/22 on Linux and Windows.
- Static and offline tests validate packaging, delegation preflight scenarios, CLI installation/update safety, and documented integration contracts.
- A focused Codex smoke test exercised delegation with an implementation worker and an independent read-only reviewer; the companion Skills were observed in `instructions-loaded` mode.
- Native host-level activation of ForgeGuard/ForgeScope as separate tools has **not** been established by those tests.
- Delegrix is **not** a standalone orchestration runtime, automatic model router, or permission authority. Actual spawning, sandboxing, model selection, and cancellation belong to the coding-agent host.
- Delegrix does not automatically merge PRs, publish releases, or deploy code.
